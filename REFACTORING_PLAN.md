# План дальнейшего рефакторинга

## Исходное состояние

Первый этап технического рефакторинга завершён:

- состояние и переходы мастера собраны в `useCalculatorWizard`;
- разрозненные строковые `provide/inject` заменены единым контекстом;
- валидность шагов вычисляется из текущих данных;
- расширения `Number.prototype` и `String.prototype` заменены чистыми функциями;
- удалено дублирование форматирования числового ввода;
- финансовые формулы, коэффициенты, пороги и тексты не изменялись.

Оставшиеся работы разделены на технические изменения и изменения, для которых
сначала необходимо подтвердить бизнес-поведение.

## Границы

Без отдельного согласования нельзя изменять:

- формулы и константы в `src/calculator.js`;
- правила определения успешного и неуспешного результата;
- порог разницы прибыли `100000`;
- тексты рекомендаций;
- порядок и смысл шагов;
- поведение внешних кнопок заявки и обратного звонка.

## Спринт 1 — тестовый контур финансовой модели

### Цель

Зафиксировать существующее поведение до рефакторинга кода, связанного с
результатами расчёта.

### Задачи

- Выбрать минимальный тестовый инструмент, совместимый с текущим Vite-проектом.
- Добавить модульные тесты для `calculator`.
- Зафиксировать сценарии с табличной и пользовательской стоимостью аренды.
- Покрыть положительную, нулевую и отрицательную маржу.
- Зафиксировать поведение при нулевом знаменателе и нечисловых значениях.
- Добавить тесты склонений и денежного форматирования.

### Требуется от владельца продукта

Подтвердить ожидаемые результаты минимум для пяти контрольных наборов входных
данных. Без этого тесты могут закрепить ошибочную формулу как правильную.

### Критерий готовности

- Контрольные бизнес-сценарии описаны явными входными и выходными значениями.
- Тесты воспроизводимо проходят локально.
- Production-сборка остаётся зелёной.

## Спринт 2 — декомпозиция компонентов результата

### Зависимость

Выполнять только после Спринта 1.

### Задачи

- Дать вычисляемым значениям в `successResult.vue` единообразные имена.
- Отделить выбор сценария результата от его HTML-разметки.
- Устранить повторение правой части успешного результата.
- Вынести повторяющиеся визуальные фрагменты в небольшие компоненты только там,
  где это действительно уменьшает количество условных веток.
- Удалить недостижимые диагностические блоки только после подтверждения тестами.
- Привести имена файлов `successResult.vue` и `failedResult.vue` к PascalCase.

### Ограничение

Условия и порядок ветвей должны остаться эквивалентными текущей реализации.

### Критерий готовности

- Каждый сценарий выбирается в одном месте.
- Одинаковая разметка не дублируется.
- Все зафиксированные сценарии показывают прежние тексты и значения.

## Спринт 3 — контракты технического состояния

### Задачи

- Определить явную структуру параметров мастера и результата расчёта.
- Рассмотреть постепенное добавление TypeScript без одновременной миграции всего
  проекта.
- Защитить публичную часть контекста от случайной мутации вне владельца.
- Разделить операции навигации, расчёта и интеграции с внешней страницей, если
  для них появятся независимые потребители.

### Критерий готовности

- Компоненты используют только документированные поля контекста.
- Ошибки в именах параметров обнаруживаются статической проверкой.
- Не добавлены абстракции без фактического потребителя.

## Спринт 4 — интеграционный слой

### Задачи

- Сделать обработчик обратного звонка явной зависимостью приложения вместо
  поиска DOM-элемента внутри composable.
- Безопасно обрабатывать отсутствие контейнера `#Newbies` в
  `support/more-features.js`.
- Убрать жёстко прописанные хешированные имена production-ассетов либо
  документировать процесс их обновления.
- Проверить загрузку внешних изображений, шрифта и поведение при их
  недоступности.

### Риск

Эти изменения затрагивают контракт со страницей, в которую встраивается
калькулятор. Перед реализацией требуется тестовая версия страницы-хоста.

### Критерий готовности

- Виджет не падает при отсутствии ожидаемого контейнера или callback-кнопки.
- Процесс публикации новых ассетов воспроизводим и задокументирован.
- Интеграция проверена на реальной или эквивалентной странице-хосте.

## Спринт 5 — качество проекта

### Задачи

- Добавить линтер для Vue и JavaScript с минимальным набором правил.
- Проверить необходимость одновременного использования Sass и Less.
- Удалить неиспользуемые зависимости только после проверки сборки.
- Привести форматирование и стиль имён к одному соглашению отдельным изменением.
- Заменить шаблонные title, favicon и язык страницы после согласования контента.
- Дополнить README командами запуска, сборки, проверки и публикации.

### Ограничение

Не смешивать массовое форматирование с функциональными или структурными
изменениями.

### Критерий готовности

- Линтер, тесты и production-сборка запускаются отдельными командами.
- В проекте нет заведомо неиспользуемых зависимостей.
- README позволяет запустить проект без знания его внутреннего устройства.

## Спринт 6 — автоматизированная проверка интерфейса

### Задачи

- Добавить smoke-тест полного прохождения шести шагов.
- Проверить табличную и пользовательскую аренду.
- Проверить переходы назад и вперёд с сохранением данных.
- Проверить Enter в числовых полях.
- Проверить reset после каждого типа результата.
- Проверить состояние disabled у кнопок навигации.
- Добавить отдельную проверку мобильной ширины.

### Критерий готовности

- Критический пользовательский маршрут проверяется одной воспроизводимой
  командой.
- Тест не зависит от внешнего production-сайта.
- В консоли браузера нет ошибок и предупреждений приложения.

## Рекомендуемый порядок

1. Зафиксировать бизнес-сценарии и добавить тесты финансовой модели.
2. Декомпозировать компоненты результата.
3. Уточнить контракты технического состояния.
4. Проверить и изолировать интеграцию со страницей-хостом.
5. Добавить статические проверки и очистить зависимости.
6. Автоматизировать критический пользовательский маршрут.

Каждый спринт следует выполнять отдельным reviewable-набором изменений. После
изменения финансовой модели или условий результата этот документ необходимо
сверить с актуальными тестами и обновить.
